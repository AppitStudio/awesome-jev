# MEM100 (agent memory engine where Jev picks relevant memories, with BM25 fallback)

[All projects](../README.md) · [Search and retrieval](README.md#search-and-retrieval)

Zero-dependency Python memory and self-improvement engine for coding agents (Antigravity, Claude Code, Cursor and others): retrieval sends one batched Jev Choice question across active memory records weighted by recency and importance, with local Okapi BM25 as the fallback when Jev is offline.

## When to use

- Give a coding agent durable memory that it can query per task.
- Mismatch: memory quality depends on what the agent writes.

## How it works

`scripts/manage_memory.py` calls `https://api.typesafe.ai/v1/systemone` once per query to choose relevant records and falls back to BM25 plus recency and importance scoring on errors. Integration evidence: [`scripts/manage_memory.py`](https://github.com/jugripa/mem100/blob/6830ee6fa6d585bc7ae19baa4887620f03fe3226/scripts/manage_memory.py).

## Get started

Initialize the memory store in your project, then query it for a task.

```sh
python3 scripts/manage_memory.py init
python3 scripts/manage_memory.py query --task "how should webhook retries be handled?"
```

Live commands may contact TypeSafe (or the configured provider) and incur charges. These commands were not run on the review host.

Memory records and the query go to TypeSafe on your key; the store stays in local files.
