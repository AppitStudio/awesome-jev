# Contribute a knowledge guide

Read the complete original and essential primary references. Write an original summary, link the source and its author, separate source claims from editorial additions, and state exactly what was tested. Do not reproduce the article or invent human review. Follow the repository's [contribution and license terms](../../CONTRIBUTING.md).

Copy [the template](ARTICLE_TEMPLATE.md) into `articles/<slug>.md` and add `articles/<slug>.json` using the version 1 contract below. Register the slug once in `collection.json`; register its controlled topics in `topics.json`. Do not remove an existing slug to retire it. Set its sidecar `status` to `retired` or `draft` as appropriate. An empty published collection requires `retire_all: true` and editorial review.

The sidecar owns identity, source/guide credits, dates, topics, FAQs, verification scope and typed connections. Markdown owns the original prose and build prompt. `id` and `slug` match the basename and do not change when a title changes. Dates are ISO `YYYY-MM-DD`; `modified_at` changes for meaningful guide revisions, not sync runs. `status` is `draft`, `published` or `retired`. Each connection has a canonical repository `path`, `kind` (`project` or `resource`), `origin` (`source-mentioned` or `jevlist-suggestion`), `purpose` (`implements-step`, `alternative`, `teaching-example` or `evaluation`), step, why, evidence URLs/paths and limitations. Project paths must be community project detail pages; native `projects/` examples are resources.

For a source author, record the public name/profile actually shown. Guide authors and reviewers have different roles; an empty reviewers list is honest. Give each guide author a `type` of `Person` or `Organization` so search engines describe the author correctly. Keep pricing, license, account and data-flow limitations beside every recommendation. The guide FAQ questions and answers must appear verbatim in Markdown and metadata; the validator checks both. A build prompt belongs in a fenced `text` block under “Copyable build prompt” when the source supports one.

An optional `image` gives the guide a search and social preview. Store a PNG, JPEG or WebP at least 1200 pixels wide in `images/` and record `path`, descriptive `alt`, `credit` and `license`, plus optional HTTPS `license_url` and `source_url`. Use an image only when its license or the rights holder's permission allows this reuse; a source link or credit alone is not permission. Without an image the site uses its default preview.

Run `node scripts/knowledge-base.mjs --write` to rebuild the guide index and project backlinks from the sidecars. Run `npm run check:knowledge` and then `npm run check`. The default command validates the schema, references, generated blocks and visible guide contract without rewriting files. These checks cannot establish that source claims or recommendations are true; review the source and upstream documentation separately.
